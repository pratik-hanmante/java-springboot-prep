JAVA COLLECTIONS — COMPLETE INTERVIEW NOTES
Updated for Modern Java (Java 8 → Java 21+)
This is a cleaned-up and corrected version of the original notes, with missing interview concepts added and inaccurate/oversimplified statements fixed.

1. COLLECTION FRAMEWORK OVERVIEW
Java Collections Framework provides interfaces, implementations, algorithms, and utility methods for storing and manipulating groups of objects.

Main hierarchy
Iterable
   |
Collection
   |
   +-- List
   |    +-- ArrayList
   |    +-- LinkedList
   |    +-- Vector
   |         +-- Stack (legacy)
   |
   +-- Set
   |    +-- HashSet
   |    +-- LinkedHashSet
   |    +-- SortedSet
   |         +-- NavigableSet
   |              +-- TreeSet
   |
   +-- Queue
        +-- PriorityQueue
        +-- Deque
             +-- ArrayDeque
             +-- LinkedList

Map is NOT a subtype of Collection
   |
   +-- HashMap
   +-- LinkedHashMap
   +-- SortedMap
   |    +-- NavigableMap
   |         +-- TreeMap
   +-- WeakHashMap
   +-- IdentityHashMap
   +-- Hashtable (legacy)
   +-- ConcurrentHashMap
Important interview point
Collection = group of individual elements
Map        = key-value pairs
Map belongs to the Collections Framework, but does NOT extend Collection.

2. LIST
A List:

Maintains a defined ordering.

Allows duplicate elements.

Allows index-based access.

Usually allows multiple nulls depending on implementation.

List<String> names = new ArrayList<>();

names.add("Messi");
names.add("Messi");       // duplicate allowed
names.add(0, "Ronaldo");  // index-based insertion

System.out.println(names);
Common implementations:

ArrayList
LinkedList
Vector
Stack (legacy)
3. ARRAYLIST
ArrayList is a resizable-array implementation of List.

List<String> players = new ArrayList<>();

players.add("Messi");
players.add("Ronaldo");

System.out.println(players.get(0));
Complexity
get(index)       -> O(1)
set(index, e)    -> O(1)
add(e)           -> O(1) amortized
add(index, e)    -> O(n)
remove(index)    -> O(n)
contains(e)      -> O(n)
Why is add(e) amortized O(1)?

Because when the internal array becomes full, a larger array is allocated and elements are copied. Most individual additions are O(1), but occasional resizing is O(n).

Important correction
Do NOT memorize that ArrayList "always grows by exactly 50%". The exact growth strategy is an implementation detail and should not be relied upon as an API guarantee.

4. LINKEDLIST
LinkedList is a doubly-linked list and also implements Deque.

LinkedList<String> list = new LinkedList<>();

list.add("A");
list.addFirst("Start");
list.addLast("End");

System.out.println(list);
Complexity
get(index)       -> O(n)
addFirst()       -> O(1)
addLast()        -> O(1)
removeFirst()    -> O(1)
removeLast()     -> O(1)
add(index, e)    -> O(n)
remove(index)    -> O(n)
Important nuance
LinkedList insertion/removal can be O(1) once the relevant node is already known.

If you first have to locate an index, locating it costs O(n).

Therefore saying "LinkedList insertion is always O(1)" is incorrect.

5. ARRAYLIST VS LINKEDLIST
Feature	ArrayList	LinkedList
Internal structure	Dynamic array	Doubly linked list
get(index)	O(1)	O(n)
add(end)	O(1) amortized	O(1)
add(index)	O(n)	O(n)
remove(index)	O(n)	O(n)
Memory overhead	Lower	Higher
Cache locality	Better	Worse
Random access	Excellent	Poor
Practical rule
Use ArrayList by default.

Use LinkedList only when its linked/deque behavior actually provides a benefit.

6. ARRAYS.ASLIST()
List<String> list = Arrays.asList("A", "B", "C");
Important:

Fixed-size list.

set() is allowed.

add() and remove() throw UnsupportedOperationException.

Changes through set() are reflected in the backing array.

The returned list is not a normal resizable ArrayList.

List<String> list =
    new ArrayList<>(Arrays.asList("A", "B", "C"));
This creates a modifiable ArrayList.

7. LIST.OF()
Modern immutable factory:

List<String> list = List.of("A", "B", "C");
Characteristics:

Unmodifiable.

Does not allow null elements.

add, remove, set throw UnsupportedOperationException.

Similarly:

Set<String> set = Set.of("A", "B", "C");

Map<String, Integer> map =
    Map.of("A", 1, "B", 2);
8. IMMUTABLE VS UNMODIFIABLE
Unmodifiable view
List<String> original =
    new ArrayList<>(List.of("A", "B"));

List<String> view =
    Collections.unmodifiableList(original);
You cannot modify through view, but changes to original can still be visible through view.

Immutable factory
List<String> immutable = List.of("A", "B");
The collection itself cannot be modified.

Interview distinction
unmodifiable = cannot modify through that reference
immutable    = collection state cannot be changed
9. SET
A Set does not allow duplicate elements.

Set<String> players = new HashSet<>();

players.add("Messi");
players.add("Messi");

System.out.println(players);
Only one logical "Messi" remains.

Common implementations:

HashSet
LinkedHashSet
TreeSet
10. HASHSET
Characteristics:

No guaranteed iteration order.

No duplicates.

Average O(1) add/contains/remove.

Allows one null element.

Internally backed by a HashMap.

Set<String> set = new HashSet<>();

set.add("Messi");
set.add("Ronaldo");
set.add("Messi");

System.out.println(set);
Important
Do not depend on HashSet iteration order.

11. LINKEDHASHSET
LinkedHashSet maintains insertion order.

Output order remains:

Messi
Ronaldo
Neymar
Average complexity is generally O(1) for basic operations.

12. TREESET
TreeSet stores unique elements in sorted order.

Set<Integer> set =
    new TreeSet<>(List.of(50, 10, 30, 20));

System.out.println(set);
Output:

[10, 20, 30, 50]
Complexity:

add      -> O(log n)
remove   -> O(log n)
contains -> O(log n)
TreeSet is backed by a tree-based sorted structure.

Null
Natural-order TreeSet does not permit null because null cannot be naturally compared.

A comparator may define its own null handling.

set.lower(30);     // < 30  -> 20
set.floor(30);     // <=30  -> 30
set.ceiling(25);   // >=25  -> 30
set.higher(30);    // >30   -> 40
Useful methods:

first()

14. MAP
A Map<K,V> stores key-value pairs.

Map<String, Integer> goals = new HashMap<>();

goals.put("Messi", 800);
goals.put("Ronaldo", 850);

System.out.println(goals.get("Messi"));
Important:

Keys are unique.

Values can be duplicated.

Calling put() with an existing key replaces its value.

goals.put("Messi", 801);
Now Messi maps to 801.

15. HASHMAP
Characteristics:

Average O(1) put, get, remove.

No guaranteed iteration order.

Allows one null key.

Allows multiple null values.

Not thread-safe.

Uses hashCode() and equals() for key lookup.

Map<String, Integer> map = new HashMap<>();

map.put("Messi", 800);
map.put("Ronaldo", 850);

System.out.println(map.get("Messi"));
16. HASHMAP INTERNAL WORKING
Simplified flow:

put(key, value)
       |
       v
key.hashCode()
       |
       v
hash spreading
       |
       v
bucket index
       |
       v
check existing key
       |
       +-- equals() matches -> replace value
       |
       +-- no match -> add new entry
Important concepts:

hashCode()
equals()
bucket
capacity
load factor
collision
resizing
treeification
Default HashMap load factor is commonly 0.75.

A resize occurs when the number of entries crosses the threshold based on capacity × load factor.

Java 8+ treeification
Heavy collisions can cause a bucket structure to become tree-based.

Important thresholds in standard HashMap implementation include:

TREEIFY_THRESHOLD = 8
UNTREEIFY_THRESHOLD = 6
MIN_TREEIFY_CAPACITY = 64
Do not simply say "if bucket size > 8, it always becomes a tree." Capacity requirements and implementation details also matter.

17. HASHMAP COLLISION
Two different keys can have the same hash value or map to the same bucket.

Key A -> hash -> bucket 5
Key B -> hash -> bucket 5
HashMap uses equals() to determine whether the keys are logically equal.

Key rule
equals() true
      =>
hashCode() MUST be same
But:

same hashCode()
      does NOT mean
equals() must be true
This is called a hash collision.

18. EQUALS() AND HASHCODE() CONTRACT
Rules:

If a.equals(b) is true, a.hashCode() == b.hashCode() must be true.

Same hash code does NOT imply objects are equal.

hashCode() should remain consistent while equality-relevant state is unchanged.

If you override equals(), override hashCode() too.

Use the same logical fields in both methods.

Example:

class Person {
    private final String id;

    Person(String id) {
        this.id = id;
    }

    @Override
    public boolean equals(Object obj) {
        if (this == obj) return true;
        if (!(obj instanceof Person other)) return false;
        return Objects.equals(id, other.id);
    }

    @Override
    public int hashCode() {
        return Objects.hash(id);
    }
}
Interview question
What happens if you override equals() but not hashCode()?

Objects that are logically equal can end up in different hash buckets, causing incorrect behavior in HashMap/HashSet.

19. LINKEDHASHMAP
Maintains a predictable iteration order.

Map<String, Integer> map =
    new LinkedHashMap<>();

map.put("Messi", 800);
map.put("Ronaldo", 850);
map.put("Neymar", 450);
By default it maintains insertion order.

It can also be configured for access order:

LinkedHashMap<String, Integer> lru =
    new LinkedHashMap<>(16, 0.75f, true);
This is useful for implementing LRU-style caches.

20. TREEMAP
TreeMap stores keys in sorted order.

Map<String, Integer> map = new TreeMap<>();

map.put("C", 3);
map.put("A", 1);
map.put("B", 2);

System.out.println(map);
Output:

{A=1, B=2, C=3}
Complexity:

put      -> O(log n)
get      -> O(log n)
remove   -> O(log n)
Supports navigation methods through NavigableMap.

21. HASHMAP VS LINKEDHASHMAP VS TREEMAP
Feature	HashMap	LinkedHashMap	TreeMap
Ordering	None guaranteed	Insertion/access order	Sorted
Average get	O(1)	O(1)	O(log n)
Null key	One	One	Usually not with natural ordering
Best use	Fast lookup	Predictable/LRU order	Sorted keys/range queries

23. PUTIFABSENT
map.putIfAbsent("Messi", 800);
Adds the mapping only if the key is not already mapped to a value.

Useful for initialization without overwriting an existing mapping.

24. COMPUTEIFABSENT
Very common interview pattern:

Map<String, List<Integer>> map = new HashMap<>();

map.computeIfAbsent("Java",
    k -> new ArrayList<>()).add(10);
If "Java" does not exist, a new ArrayList is created.

25. MERGE
Useful for counters:

Map<String, Integer> counts = new HashMap<>();

counts.merge("Java", 1, Integer::sum);
counts.merge("Java", 1, Integer::sum);

System.out.println(counts);
Result:

Java = 2
26. MAP ITERATION
Preferred modern style:

map.forEach((key, value) ->
    System.out.println(key + " = " + value));
Or:

for (Map.Entry<String, Integer> entry : map.entrySet()) {
    System.out.println(entry.getKey());
    System.out.println(entry.getValue());
}
Important
If you need both key and value, entrySet() is generally preferable to iterating over keySet() and repeatedly calling get().

28. SORTING
Natural ordering:

Collections.sort(players);
Modern style:

players.sort(Comparator.naturalOrder());
Reverse:

players.sort(Comparator.reverseOrder());
By string length:

players.sort(
    Comparator.comparingInt(String::length)
);
Multiple criteria:

players.sort(
    Comparator.comparing(Player::getAge)
              .thenComparing(Player::getName)
);
29. COMPARABLE VS COMPARATOR
Comparable
Defines natural ordering inside the class.

class Player implements Comparable<Player> {

    private int age;

    @Override
    public int compareTo(Player other) {
        return Integer.compare(this.age, other.age);
    }
}
Usage:

Collections.sort(players);
Comparator
Defines external/custom ordering.

Comparator<Player> byName =
    Comparator.comparing(Player::getName);

players.sort(byName);
Interview answer
Comparable = one natural ordering
Comparator = multiple/custom orderings

Complexity:

O(log n)
If not found, the result is negative and encodes the insertion point.

Collections.copy(destination, source);

39. ITERATOR
Used to traverse collections.

Iterator<String> iterator =
    list.iterator();

while (iterator.hasNext()) {
    String value = iterator.next();
    System.out.println(value);
}
Safe removal during iteration:

Iterator<String> it = list.iterator();

while (it.hasNext()) {
    if (it.next().equals("Messi")) {
        it.remove();
    }
}
Do NOT structurally modify the list directly while using a normal iterator.

40. LISTITERATOR
ListIterator works specifically with lists and supports traversal in both directions.

ListIterator<String> it =
    list.listIterator();

while (it.hasNext()) {
    System.out.println(it.next());
}

while (it.hasPrevious()) {
    System.out.println(it.previous());
}
It also supports:

add()
remove()
set()
41. FAIL-FAST
Many standard collection iterators are fail-fast on a best-effort basis.

Example:

List<Integer> numbers =
    new ArrayList<>(List.of(1, 2, 3, 4));

for (Integer n : numbers) {
    if (n == 3) {
        numbers.add(10);
    }
}
This will typically result in:

ConcurrentModificationException
Important correction
Fail-fast is NOT a thread-safety guarantee.

It is also not guaranteed in every possible situation; it is generally best-effort behavior.

42. FAIL-SAFE — IMPORTANT TERMINOLOGY CORRECTION
"Fail-safe iterator" is common interview terminology, but it is NOT an official Java Collections Framework classification.

For example:

CopyOnWriteArrayList<String> list =
    new CopyOnWriteArrayList<>(
        List.of("A", "B", "C")
    );

for (String item : list) {
    list.add("D");
}
The iterator uses a snapshot-like mechanism, so modification does not cause the same ConcurrentModificationException behavior as a normal ArrayList iterator.

Better interview wording
Say:

"Concurrent collections may provide weakly consistent or snapshot-style iteration rather than fail-fast iteration."

43. COPYONWRITEARRAYLIST
CopyOnWriteArrayList<String> list =
    new CopyOnWriteArrayList<>();
Characteristics:

Thread-safe.

Every structural write creates a new underlying array.

Iterators operate over a snapshot.

Excellent when reads greatly outnumber writes.

Expensive for frequent writes.

Good use case:

many reads
few writes
44. CONCURRENT HASHMAP
Map<String, Integer> map =
    new ConcurrentHashMap<>();
Characteristics:

Thread-safe.

Designed for concurrent access.

Does not allow null keys or null values.

Better concurrency than synchronizing an entire HashMap.

Iterators are weakly consistent and do not normally throw ConcurrentModificationException due to concurrent modifications.

Important correction
Do NOT say modern ConcurrentHashMap simply uses "segment-level locking".

That description is associated with older implementations.

Modern Java 8+ ConcurrentHashMap uses techniques such as CAS, synchronized locking on bins when needed, and other concurrency mechanisms.

45. SYNCHRONIZED COLLECTIONS
List<String> list =
    Collections.synchronizedList(
        new ArrayList<>()
    );
Individual collection operations are synchronized.

Iteration still needs external synchronization
synchronized (list) {
    for (String item : list) {
        System.out.println(item);
    }
}
46. SYNCHRONIZED VS CONCURRENT
Collections.synchronizedList(...)
    |
    +-- synchronized wrapper
    +-- simple protection
    +-- iteration needs external synchronization

ConcurrentHashMap / concurrent collections
    |
    +-- designed for concurrent workloads
    +-- generally better scalability
    +-- specialized concurrency semantics
47. QUEUE
Queue generally follows FIFO:

First In -> First Out
Queue<String> queue =
    new LinkedList<>();

queue.offer("First");
queue.offer("Second");
queue.offer("Third");

System.out.println(queue.peek());
System.out.println(queue.poll());
Methods:

offer() -> insert, returns false if unable
add()   -> insert, may throw exception

peek()  -> inspect head, returns null if empty
element()-> inspect head, may throw exception

poll()  -> remove head, returns null if empty
remove()-> remove head, may throw exception
48. DEQUE
Deque = Double Ended Queue.

Deque<String> deque =
    new ArrayDeque<>();

deque.addFirst("A");
deque.addLast("B");

deque.removeFirst();
deque.removeLast();
Can behave as:

Queue
Stack
49. ARRAYDEQUE VS STACK
Prefer ArrayDeque for stack behavior in modern Java.

Deque<Integer> stack =
    new ArrayDeque<>();

stack.push(10);
stack.push(20);

System.out.println(stack.pop());
This follows LIFO:

Last In -> First Out
Stack is a legacy class extending Vector.

50. PRIORITYQUEUE
PriorityQueue is heap-based.

Default:

Min-heap behavior
PriorityQueue<Integer> pq =
    new PriorityQueue<>();

pq.offer(5);
pq.offer(2);
pq.offer(8);
pq.offer(1);

System.out.println(pq.peek()); // 1
Max heap:

PriorityQueue<Integer> maxHeap =
    new PriorityQueue<>(Comparator.reverseOrder());
Complexity:

offer -> O(log n)
poll  -> O(log n)
peek  -> O(1)
Important
Iterating over a PriorityQueue does NOT guarantee sorted order.

Only repeated poll() gives elements according to priority.

List
- ordered
- duplicates allowed
- index based

Set
- unique elements
- no index
- ordering depends on implementation

Map
- key-value
- keys unique

52. HASHSET VS TREESSET VS LINKEDHASHSET
HashSet
    -> uniqueness
    -> fast average lookup
    -> no guaranteed order

LinkedHashSet
    -> uniqueness
    -> insertion order

53. HASHMAP VS HASHTABLE
Hashtable is legacy.

HashMap
- modern
- not synchronized
- allows one null key
- allows null values

Hashtable
- legacy
- synchronized
- does not allow null key/value
Prefer modern alternatives unless legacy compatibility requires Hashtable.

54. VECTOR VS ARRAYLIST
Vector
- legacy
- synchronized methods
- generally slower for modern single-threaded use

ArrayList
- modern
- not synchronized
- usually preferred
Do not rely on simplistic statements such as "Vector always doubles" or "ArrayList always grows by 50%" because capacity growth is implementation-specific.

55. WEAKHASHMAP
WeakHashMap stores keys using weak references.

If a key is no longer strongly reachable elsewhere, it may be garbage collected and its mapping may disappear.

Map<Object, String> cache =
    new WeakHashMap<>();

Object key = new Object();

cache.put(key, "value");

key = null;

System.gc(); // only a suggestion
Important
System.gc() does NOT guarantee immediate garbage collection.

WeakHashMap can be useful in memory-sensitive association/cache-like scenarios.

56. IDENTITYHASHMAP
IdentityHashMap compares keys using reference identity (==) rather than normal equals() semantics.

String a = new String("Key");
String b = new String("Key");

Map<String, Integer> map =
    new IdentityHashMap<>();

map.put(a, 1);
map.put(b, 2);
Since:

a != b
both references can exist as separate keys.

57. ENUMSET
Specialized Set for enum values.

enum Day {
    MONDAY, TUESDAY, WEDNESDAY,
    THURSDAY, FRIDAY, SATURDAY, SUNDAY
}

EnumSet<Day> weekdays =
    EnumSet.range(Day.MONDAY, Day.FRIDAY);
Very efficient for enum values.

58. ENUMMAP
Specialized Map whose keys are enum values.

EnumMap<Day, String> map =
    new EnumMap<>(Day.class);

map.put(Day.MONDAY, "Work");
Efficient and compact for enum keys.

64. STREAM VS COLLECTION
Collection
    -> stores data

Stream
    -> processes data
A Stream:

does not store elements itself.

is generally lazy.

can be consumed once.

supports intermediate and terminal operations.

Example:

List<String> result =
    players.stream()
           .filter(...)
           .map(...)
           .toList();
65. STREAM LAZY EVALUATION
Intermediate operations are lazy:

players.stream()
       .filter(...)
       .map(...);
Nothing useful happens until a terminal operation is invoked.

Terminal examples:

collect()
toList()
count()
forEach()
reduce()
findFirst()
anyMatch()
66. OPTIONAL WITH MAP LOOKUPS
Avoid unnecessary null checks:

Optional<Integer> goals =
    Optional.ofNullable(map.get("Messi"));
But do not blindly use Optional everywhere.

For a Map lookup, these are often simpler:

map.getOrDefault("Messi", 0);

Collections should normally use generics.

Bad:

List list = new ArrayList();
Good:

List<String> list =
    new ArrayList<>();
Benefits:

Compile-time type safety.

Less casting.

Cleaner code.

? extends
Read-oriented / producer:

List<? extends Number> numbers;
You can safely read Number values, but generally cannot add arbitrary Number values.

? super
Write-oriented / consumer:

List<? super Integer> numbers;
You can safely add Integer values.

PECS
Producer Extends
Consumer Super
Very common interview question.

74. COLLECTIONS AND CONCURRENT MODIFICATION
This is dangerous:

for (String s : list) {
    if (s.equals("A")) {
        list.remove(s);
    }
}
Safer:

list.removeIf(s -> s.equals("A"));
Or:

Iterator<String> it = list.iterator();

while (it.hasNext()) {
    if (it.next().equals("A")) {
        it.remove();
    }
}

    new HashMap<>();

    frequency.merge(

        1,
        Integer::sum

if (map.containsKey(word)) {

78. PRIORITYQUEUE INTERVIEW PATTERN
Find the K largest elements:

PriorityQueue<Integer> pq =
    new PriorityQueue<>();

for (int n : nums) {
    pq.offer(n);

    if (pq.size() > k) {
        pq.poll();
    }
}
At the end, the heap contains the K largest elements.

This is a very common DSA/interview use case.

80. HASHSET INTERVIEW TRAP
HashSet internally uses a HashMap.

Conceptually:

HashSet element
      |
      v
HashMap key
      |
      v
dummy PRESENT value
Therefore HashSet uniqueness relies on hash/equality behavior.

81. TREESET INTERVIEW TRAP
TreeSet determines uniqueness based on its ordering comparison.

If:

compare(a, b) == 0
TreeSet treats them as equivalent for set purposes, even if:

a.equals(b) == false
Therefore ordering should generally be consistent with equals when logical equality matters.

82. COMPARATOR NULL HANDLING
You can explicitly handle nulls:

Comparator<String> comparator =
    Comparator.nullsFirst(
        Comparator.naturalOrder()
    );
Or:

Comparator<String> comparator =
    Comparator.nullsLast(
        Comparator.naturalOrder()
    );
Useful when sorting data containing null values.

players.sort(

86. MOST IMPORTANT INTERVIEW QUESTIONS
1. ArrayList vs LinkedList?
ArrayList uses a dynamic array and provides O(1) random access. LinkedList uses a doubly linked list and provides O(n) indexed access but O(1) insertion/removal at known ends/nodes.

2. HashMap vs Hashtable?
HashMap is modern and unsynchronized and permits nulls. Hashtable is legacy, synchronized, and does not permit null keys/values.

3. HashMap vs ConcurrentHashMap?
HashMap is not thread-safe. ConcurrentHashMap is designed for concurrent access and does not permit null keys/values.

4. HashSet internally uses what?
HashMap.

5. How does HashMap find a key?
Uses hashCode/hash spreading to locate a bucket and equals() to identify the matching key.

6. Why override hashCode when overriding equals?
Equal objects must have equal hash codes for hash-based collections to work correctly.

7. Comparable vs Comparator?
Comparable defines natural ordering. Comparator defines external/custom ordering.

8. ArrayList vs CopyOnWriteArrayList?
ArrayList is not thread-safe. CopyOnWriteArrayList is thread-safe and optimized for read-heavy concurrent workloads.

9. HashSet vs TreeSet?
HashSet provides average O(1) lookup with no guaranteed order. TreeSet provides sorted order with O(log n) operations.

10. HashMap vs TreeMap?
HashMap provides average O(1) lookup with no guaranteed order. TreeMap keeps keys sorted with O(log n) operations.

11. What is fail-fast?
An iterator may detect structural modification and throw ConcurrentModificationException on a best-effort basis.

12. What is fail-safe?
Not an official Java API term. Prefer saying weakly consistent or snapshot-style iteration depending on the collection.

13. Why is String a good HashMap key?
String is immutable and provides stable equals/hashCode behavior.

14. Can mutable objects be HashMap keys?
They can, but changing equality/hashCode-relevant state after insertion can make the entry effectively unreachable through normal lookup.

15. What is PECS?
Producer Extends, Consumer Super.

90. COMMON MISTAKES TO AVOID
❌ "HashMap is always O(1)"
✅ Average-case O(1); worst-case depends on collisions/implementation.

❌ "LinkedList insertion is always O(1)"
✅ O(1) when the node/position is already known; locating an index costs O(n).

❌ "ConcurrentHashMap uses segment locking"
✅ This is an outdated oversimplification for modern Java.

❌ "Fail-safe is an official Java collection category"
✅ It is common interview terminology, not an official API classification.

❌ "ArrayList always grows by 50%"
✅ Growth strategy is implementation-specific.

❌ "PriorityQueue iteration is sorted"
✅ It is not guaranteed to be sorted; use poll() repeatedly.

❌ "HashSet maintains order"
✅ HashSet has no guaranteed iteration order.

❌ "TreeSet uses equals() for uniqueness"
✅ TreeSet primarily uses ordering/comparison; compare == 0 means equivalent for set purposes.

❌ "Map extends Collection"
✅ Map is a separate hierarchy.

❌ "System.gc() guarantees GC"
✅ It only requests/suggests garbage collection.

❌ "Arrays.asList() is a normal ArrayList"
✅ It is a fixed-size list backed by the array.

❌ "List.of() can contain null"
✅ List.of() rejects null elements.
